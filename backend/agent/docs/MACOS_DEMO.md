# Показ CLI на macOS

Демонстрация запускает существующий CLI, официальный parser, LangChain-агента,
настоящий HTTP-сервис testing_tools и настоящий Schemathesis. Ответы LLM задаёт
локальный сценарный имитатор: он запрашивает вызов инструмента, принимает его
результат и завершает ответ. Это показ CLI и программной интеграции, не качества
решений настоящей модели и не генератора собственных pytest-файлов.

Docker, Java и API-ключ модели для этого сценария не нужны. Сеть нужна для
первого клонирования, установки Python и зависимостей. После установки серверы
демонстрации работают на localhost и завершаются при окончании показа.

## Подготовить Mac до занятия

Понадобятся Git и uv. Если уже установлен Homebrew:

```bash
brew install uv
```

Другие способы: https://docs.astral.sh/uv/getting-started/installation/.
Нужен доступ к репозиторию через свой GitHub-аккаунт.

В Terminal:

```bash
git clone --branch model https://github.com/OsipShmel/arqua-1.git arqa-cli-demo
cd arqa-cli-demo
uv sync --locked --all-packages --all-extras --python 3.13
```

Если Python 3.13 отсутствует, uv может установить его автоматически.
Все следующие команды выполняются из `arqa-cli-demo`. Переносить Windows-папку
`.venv` на Mac не следует: окружение создаёт uv на самом Mac.

Если этот клон уже есть, обновите его через `git pull --ff-only` и повторите sync.
Для показа используйте `--no-sync --no-project`, чтобы запускать подготовленное
окружение без обращения uv к установке зависимостей.

## Показать преподавателю

### 1. Справка существующего CLI

```bash
uv run --no-sync --no-project arqa-testgen --help
uv run --no-sync --no-project arqa-testgen generate --help
```

Поясните: контракт принимается из файла или URL; пользователь задаёт адрес API,
разрешённые tools, таймауты и каталог результатов. Инструменты выбирает и вызывает агент.

### 2. Успешный запуск с обнаружением дефекта

```bash
uv run --no-sync --no-project python backend/agent/examples/demo_cli.py
```

Скрипт поднимет стенд и выведет фактическую команду CLI. В контракте `id` должен
быть integer; стенд возвращает строку `wrong-type`. Schemathesis обнаружит
`response_schema_conformance`. CLI выведет результат и пути JSON, Markdown,
manifest, журнала и JUnit. Скрипт также проверит наличие этой находки и JUnit;
повторный запуск создаёт новый каталог с датой и временем.

В конце должно быть:

```text
Статус вызова агента: success
Результат проверок API: failed
```

`success` означает, что обращение к агенту прошло успешно. `failed` означает
обнаруженный дефект API. Это разные результаты, которые CLI сохраняет отдельно.

### 3. Открыть результаты

```bash
open runs
```

В Finder откройте последний `teacher-demo-*`, затем `reports`, каталог прогона
и `report.md` или `report.json`. Журнал — `events.jsonl`; JUnit находится внутри
`tool_artifacts`. Все пути напечатаны в терминале. Для открытия файла в TextEdit
можно использовать `open -a TextEdit "/путь/из/терминала/report.md"`.

### 4. Обработка неверного ввода

```bash
uv run --no-sync --no-project arqa-testgen generate missing-demo-contract.yaml --base-url http://localhost:8080
```

При отсутствии такого файла CLI сообщит, что контракт не найден, вернёт код 1
и сохранит отчёт об ошибке. Модель при этой ошибке не вызывается.

## Объяснение своей части

«Я реализовал консольный интерфейс: ввод контракта и параметров, подключение
командного парсера, подготовку контекста, запуск агента с ограничениями времени,
обработку ошибок и сохранение отчётов. Агент сам вызывает инструменты. В этом
показе LLM имитируется локально, а проверку API выполняет настоящий Schemathesis».

Полный сценарий с настоящей LLM потребует отдельной настройки провайдера по
корневому README; менять код CLI для этого не требуется.
