# Демо-микросервисы

Два сервиса для оценки прототипа и сравнения с baseline-инструментами (ТЗ, раздел 4).
Источник истины — контракт `openapi.yaml`, написанный руками. Сервис отдаёт его как
`GET /openapi.yaml`. В коде намеренно заложены дефекты — расхождения с контрактом.
Их список ниже — это эталон для расчёта **Fault Detection Rate**: доля дефектов из
таблицы, которые нашёл инструмент или тесты агента.

| Сервис     | Каталог     | Порт (compose) | Контракт                             |
|------------|-------------|----------------|--------------------------------------|
| Petstore   | `petstore/` | 18081          | `http://localhost:18081/openapi.yaml`|
| Orders     | `orders/`   | 18082          | `http://localhost:18082/openapi.yaml`|

## Запуск

Всё вместе (testing_tools, Microcks и оба сервиса), из корня репозитория:

```bash
docker compose up --build
```

Внутри compose-сети сервисы доступны как `http://petstore:8080` и `http://orders:8080` —
эти адреса и передавайте в `target.base_url` и `contract.url`.

Без Docker, из каталога `demo/` (FastAPI и uvicorn берутся из окружения testing_tools):

```bash
PYTHONPATH=. uv run --package testing-tools uvicorn --app-dir petstore app:app --port 18081
```

```bash
PYTHONPATH=. uv run --package testing-tools uvicorn --app-dir orders app:app --port 18082
```

Состояние хранится в памяти и сбрасывается при перезапуске сервиса.

## Эталонные дефекты

### Petstore

| ID | Операция               | Как воспроизвести                         | Что не так                                                  |
|----|------------------------|-------------------------------------------|-------------------------------------------------------------|
| P1 | `GET /pets`            | `?limit=101`                              | 500 вместо 400 (по контракту `limit` ≤ 100)                 |
| P2 | `POST /pets`           | `{"name": ""}`                            | 500 вместо 422 (`name` — `minLength: 1`)                    |
| P3 | `POST /pets`, `GET /pets/{petId}`, `GET /pets` | создать питомца и прочитать его | в ответе нет обязательного поля `status`               |
| P4 | `DELETE /pets/{petId}` | `DELETE /pets/999`                        | 200 `{"deleted": false}` вместо 404                         |

### Orders

| ID | Операция                        | Как воспроизвести                                       | Что не так                                                  |
|----|---------------------------------|---------------------------------------------------------|-------------------------------------------------------------|
| O1 | `POST /orders`                  | `{"items": [{"sku": "croissant", "quantity": -3}]}`     | 201 вместо 422 (`quantity` ≥ 1), `total` отрицательный      |
| O2 | `POST /orders`                  | `{"items": [{"sku": "croissant", "quantity": 3}]}`      | `total` — строка `"7.50"`, а по контракту число             |
| O3 | `POST /orders/{orderId}/cancel` | отменить заказ дважды                                    | 500 вместо 409                                              |
| O4 | `GET /orders/{orderId}`         | прочитать отменённый заказ                               | `status: "canceled"` — нет в enum `[new, cancelled]`        |

## Что находят baseline-инструменты

Проверено прогонами через testing_tools (`seed=1`):

| Инструмент                              | Petstore           | Orders              |
|-----------------------------------------|--------------------|---------------------|
| Schemathesis (`max_examples=50`, все фазы) | 4/4 (P1–P4)     | 2/4 (O3, O4)        |
| EvoMaster (`max_time_s=60`)             | 2/4 (P3, P4)       | 3/4 (O2, O3, O4)    |
| Microcks (примеры из контракта)         | 2/4 (P3, P4)       | 0/4                 |

O1 не находит ни один инструмент: отрицательное количество проходит, только если товар
существует, а случайные `sku` почти всегда дают 404. Такие дефекты требуют понимания
предметной области — здесь ожидается выигрыш тестов, сгенерированных агентом.

Один дефект обычно даёт несколько находок (например, P3 видна в трёх операциях),
поэтому FDR считается по таблице дефектов, а не по числу `findings`.
