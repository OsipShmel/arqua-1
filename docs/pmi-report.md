# ARQA-1: готовность по ПМИ

Проверка ветки `develop` (коммит `d190bc2`) по «ПМИ ARQA-1, Приложение А. Контрольные
примеры» (А-1…А-25). Дата: 2026-11-09. Стенды: macOS (Python 3.13, uv 0.12) и Docker:
контейнеры из `docker-compose.yml` (testing_tools, Microcks, Petstore, Orders) плюс
контейнер тестов на чистом Linux с установкой из `uv.lock`. Модели: удалённая
`qwen3.8-flash-next` (DeepCode) и локальная `qwen3.6:35b-a3b` (Ollama).

Каждый пример ПМИ переведён в автотест: [tests/acceptance](../tests/acceptance/README.md).
Тест, который проходит, подтверждает требование. Тест с `xfail(strict=True)` описывает
известный пробел и сам «покраснеет», когда его закроют. Самого ТЗ в репозитории нет,
поэтому ссылки ПМИ на пункты ТЗ (4.1.2.4, 4.1.6.2, 4.1.7.2, 4.8.1.1, таблица 2,
раздел 6.2) проверены только в той части, которая видна из ПМИ.

Главная причина красных строк одна: **в агенте нет генератора pytest-тестов**.
`run_qa_agent` вызывает инструменты (Schemathesis, Microcks) и возвращает текстовый ответ
модели, но никогда не возвращает файлы тестов. Поэтому не выполняются генерация (А-4,
А-5, А-23), самокоррекция (А-7) и всё, что считается по собственным тестам системы:
метрики (А-13), их повторяемость (А-15), сравнение с baseline (часть А-14). При этом
инфраструктура под генератор готова: CLI сохраняет файлы из ответа агента (AgentResult v1),
а testing_tools умеет прогнать набор pytest и посчитать по нему Runnability, Mutation
Score и Contract Coverage.

## Что уже работает

- **Контракт.** OpenAPI 3.x из файла или URL, JSON или YAML (формат по содержимому),
  локальные `$ref`, рекурсивные схемы. Битый контракт не роняет CLI: ошибка, код 1,
  отчёт.
- **Контекст для модели.** Summary по операциям: используемые схемы, ограничения,
  примеры, security, связи из OpenAPI `links`; vendor-расширения и неиспользуемые схемы
  отбрасываются. Полный контракт модели не отправляется. Опционально — статический
  разбор Python-исходников.
- **Агент.** LangChain с моделью через любой OpenAI-совместимый API (`.env`, без правки
  кода); лимиты времени процесса и шагов графа; таймаут запроса к LLM 60 с и один повтор.
- **Инструменты через testing_tools.** Schemathesis (по умолчанию) и Microcks; модели
  возвращается сжатая сводка (≤ 24 000 символов, до 10 находок), полные результаты и
  артефакты — на диск.
- **testing_tools как самостоятельный сервис.** REST API, Schemathesis, Microcks, runner
  pytest-наборов с сетевой изоляцией, мутационное тестирование ответов, метрики
  (Contract Coverage по операциям и кодам, находки, Test Suite Size, Runnability,
  Mutation Score), Markdown-отчёт, архив прогонов по дате и времени, таймауты с
  частичными результатами.
- **Отчёты и воспроизводимость.** Новый каталог на каждый запуск; `report.json`,
  `report.md`, `manifest.json` (версии пакетов, Git, хеши кода, lock-файла, контракта),
  `events.jsonl` (этапы, вызовы LLM и инструментов), `runtime.json` (модель, параметры,
  версия промпта, токены).
- **Безопасность.** Ключей в репозитории нет, `.env` не в Git, URL с учётными данными CLI
  отклоняет, ключ провайдера вырезается из отчётов, тесты агента не могут выйти в сеть
  мимо тестируемого сервиса.

## Проблемы

Подробное описание с местами в коде, воспроизведением и тестами —
[docs/known-issues.md](known-issues.md). Коротко, по убыванию важности:

1. Нет генератора pytest и самокоррекции (А-4, А-5, А-7, А-13, А-15, А-23).
2. Ошибка инструмента или модели обрывает весь прогон агента (BUG-01).
3. EvoMaster есть в агенте, но не в сервисе (BUG-02).
4. Результат заглушки не помечен, модель выдаёт его за реальный (BUG-03).
5. Маскирование ключа портит отчёты при коротком ключе (BUG-04).
6. Причина «стенд недоступен» не видна в отчёте CLI (BUG-05).
7. API testing_tools принимает учётные данные в URL сервиса (BUG-06).
8. Агент не может отправить тесты в runner (BUG-07).
9. Непонятные сообщения об ошибках, связи из parser не в summary, завышенное число
   находок, невоспроизводимый FDR на Orders, у CLI нет Docker-образа (BUG-08…12, INF-01).

## Что исправлено в этой ветке

- `backend/testing_tools/.python-version` был `3.14` при workspace и `.venv` на 3.13: uv
  внутри каталога пакета выбирал другой интерпретатор, и `uv run` оттуда пересобирал бы
  общий `.venv`. Теперь `3.13`, как в корне.
- Корневой `pyproject.toml` зависел только от `agent`; теперь от всех трёх пакетов, плюс
  dev-группа с pytest и конфиг pytest для приёмки. `uv.lock` обновлён.
- CI запускал только тесты CLI и parser. Добавлены тесты testing_tools, mypy и приёмка.
- README: корневой переписан как обзор системы и быстрый старт; руководство CLI
  перенесено и дополнено в `backend/agent/README.md`; написан README для
  `openapi-parser`; уточнены README testing_tools и `DEMO.md`.

- Добавлен прогон всех наборов в Docker: `tests/docker/` (образ на чистом Linux из
  `uv.lock`, compose-override с контейнером тестов в сети стенда) и стендовые тесты
  `tests/acceptance/test_stand_docker.py`.
