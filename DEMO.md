# Демонстрация модуля testing_tools

Модуль — HTTP-сервис, которому ИИ-агент отправляет конфиг запуска инструментов
тестирования API и получает метрики качества. Внутри работают четыре инструмента:

- **Schemathesis** — быстрый фаззинг API по контракту (baseline-инструмент из ТЗ);
- **EvoMaster** — глубокий эволюционный поиск по контракту (baseline-инструмент из ТЗ);
- **Microcks** — контрактные тесты по примерам из контракта (baseline-инструмент из ТЗ);
- **мутационное тестирование** — оценка качества тестов, сгенерированных агентом:
  модуль портит ответы сервиса и проверяет, заметят ли это тесты (Mutation Score,
  Runnability).

Стенд поднимается одной командой: модуль, Microcks и два демо-сервиса с заранее
известными дефектами (`demo/README.md`).

## Что нужно

- Docker Desktop (запущенный);
- `uv` и Python 3.14 — только для автотестов (шаг 1);
- для шага 3 хватит системного `python3`.

## 1. Автотесты (≈30 с)

Из `backend/testing_tools`:

```bash
uv run pytest
```

Ожидаемо: `141 passed, 1 skipped`. Тесты по-настоящему запускают Schemathesis, прокси
для мутаций и pytest против тестового сервиса с багами. Microcks в автотестах заменён
имитацией его API, EvoMaster проверяется на настоящем отчёте; вживую оба работают на
шаге 3. Пропущенный тест — живой запуск EvoMaster, он включается так:
`EVOMASTER_JAR=/путь/к/evomaster.jar uv run pytest`.

## 2. Поднять стенд

Из корня репозитория:

```bash
docker compose up --build -d
```

Первая сборка — несколько минут. Проверить, что всё поднялось:

```bash
curl -s localhost:8000/health
```

Ожидаемо: `{"status":"ok", ..., "tools":{"schemathesis":true,"microcks":true,"mutation":true,"evomaster":true}}`.

Что где:

| Адрес                        | Что это                                   |
|------------------------------|-------------------------------------------|
| http://localhost:8000/docs   | Swagger модуля — можно слать запросы руками |
| http://localhost:8585        | UI Microcks                               |
| http://localhost:18081/openapi.yaml | контракт демо-сервиса Petstore     |
| http://localhost:18082/openapi.yaml | контракт демо-сервиса Orders       |

## 3. Прогон «как агент»

`examples/run_demo.py` делает то же, что агент: отправляет конфиг, опрашивает статус,
получает результат и сохраняет Markdown-отчёт. Из `backend/testing_tools/examples`:

```bash
python3 run_demo.py petstore
```

```bash
python3 run_demo.py orders
```

Каждый прогон — около 2 минут для Petstore и 2.5 для Orders (из них 60 с — бюджет
EvoMaster). Скрипт печатает метрики, находки каждого инструмента, упавшие тесты с
причиной падения и путь к отчёту `report-*.md`. Без EvoMaster быстрее:
`python3 run_demo.py petstore --tools mutation microcks schemathesis`.

> Тесты в `examples/sample_agent_tests/` написаны вручную и играют роль вывода
> агента: на них видно, как модуль оценивает сгенерированные тесты.

Перед повторным показом сбросьте состояние демо-сервисов (Schemathesis создаёт и
удаляет данные):

```bash
docker compose restart petstore orders
```

## Что показать

**1. Сравнение с baseline-инструментами.** В демо-сервисах 8 известных дефектов. Результат
прогона на этом стенде:

| Кто искал                       | Petstore (P1–P4) | Orders (O1–O4) | Fault Detection Rate |
|---------------------------------|------------------|----------------|----------------------|
| Тесты «агента» (`sample_agent_tests`) | 4/4        | 4/4            | 100%                 |
| Schemathesis (быстрый, ~10 с)   | 4/4              | 2/4            | 75%                  |
| EvoMaster (глубокий, 60 с)      | 2/4 (P3, P4)     | 3/4 (O2–O4)    | 62.5%                |
| Microcks                        | 2/4              | 0/4            | 25%                  |

Baseline-инструменты дополняют друг друга. EvoMaster нашёл O2 (`total` строкой), которую
не видит Schemathesis: он умеет собирать валидный заказ из ответа `GET /products`. Зато за
60 с он не добрался до P1 и P2. O1 (отрицательное количество) не нашёл ни один
инструмент — здесь нужно понимать смысл поля. Тесты, учитывающие смысл API, находят
всё — в этом смысл ИИ-агента.

**2. Метрики из ТЗ** — в выводе скрипта и в отчёте:

| Метрика           | Petstore | Orders | Откуда                                   |
|-------------------|----------|--------|------------------------------------------|
| Contract Coverage | 100% операций, 80% кодов ответов | 100%, 86.7% | Schemathesis + Microcks   |
| Test Suite Size   | 8        | 9      | тесты агента                             |
| Runnability       | 50%      | 55.6%  | доля тестов, прошедших без правки        |
| Mutation Score    | 100%     | 40.5%  | доля «испорченных» ответов, которые тесты заметили |
| Покрытие контракта тестами агента | 100% операций, 40% кодов | 100%, 46.7% | запросы тестов через прокси |

Runnability ниже 100%, потому что упавшие тесты — это ровно те, что поймали реальные
дефекты сервиса: у каждого в отчёте причина «дефект сервиса» (а не «ошибка теста» или
«инфраструктура») и диагностическое сообщение. Mutation Score для Orders 40.5%: отчёт показывает выжившие
мутанты — например, тесты не проверяют поле `name` у товара.

**3. Markdown-отчёт** — `examples/report-*.md`, или по ссылке
`http://localhost:8000/api/v1/runs/<run_id>/artifacts/run-report.md`.

**4. Сохранение результатов** с версионированием по дате и времени:

```bash
docker compose exec testing-tools ls /data/results
```

Каталоги вида `20261012T174925Z_<run_id>/` с `result.json`, `report.md`, запросом и
сырыми отчётами инструментов. После `docker compose restart testing-tools` результаты
по-прежнему отдаются через API.

**5. Изоляция тестов агента.** Тесту разрешено ходить только в тестируемый сервис:
попытка обратиться к другому сервису или в интернет падает с
`network access to ... is blocked`.

**6. Microcks UI.** Пока прогон идёт, в http://localhost:8585 видно импортированный
сервис и тест. После прогона модуль удаляет сервис (`cleanup=true` по умолчанию).

## Остановить

```bash
docker compose down
```

Чтобы удалить и сохранённые результаты — `docker compose down -v`.
